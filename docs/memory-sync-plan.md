# SQLite 与 Cloudflare 记忆同步：最小实现计划

状态：SQLite 已成为插件/CLI/MCP 唯一运行时后端；显式 init/import（migrate 别名）/export 与 dry-run 已实现。运行时现在兼容 v1 与显式升级后的 v2，普通 record/update 已原子写入同步操作、版本、稳定章节身份、投影和 outbox。新库仍初始化为 v1，普通读写不升级。record 返回 logicalPath，name 保留 .md，正文保留 Markdown。用户确认真实记忆已在此前完成 SQLite 迁移；本轮仅使用合成数据，未访问真实记忆或凭据、未创建云资源。见 [SQLite 里程碑](memory-sqlite-milestone.md) 与 [同步集成里程碑](memory-sync-milestone.md)。

## 目标与边界

- 单用户、多设备、本地优先；SQLite 明文保存正文并执行检索，断网照常读写。
- Workers 提供同步 API，D1 保存变更及版本；按空间可选端到端加密。
- 数据库是唯一运行时主存储；Markdown 用于显式导入、导出和迁移校验。
- 保持 recall/search/read/record/update、渐进读取、章节更新及现有权限规则。
- 宿主机仅需 Docker 和启动脚本，使用镜像中固定版本的 Bun 程序；不临时 bun x 下载依赖。
- 第一版不做多人账号、向量检索、管理网页、自动调度、附件或 R2。
- 云服务限制、价格、D1 事务/条件写入语义及加密实现须在编码前核对官方文档，并记录核对结果。

## 1. 本地存储与兼容入口

SQLite 为唯一运行时后端，要求显式绝对 root，与工作树和 cwd 无关。
init 可重复；普通写入也允许初始化空库，读取不创建库，启动不自动导入。
导入先校验所有选定空间，再逐空间事务提交；跨空间不保证原子性，重试幂等。
共用调用方策略与校验逻辑，避免换后端时丢失 serious/build/plan/casual 权限和只读限制。

建议每个空间一个 SQLite 文件，便于独立挂载、导出及同步凭据授权。使用 Bun SQLite、事务、WAL、busy timeout 和 schema 版本管理。

最小数据模型：

- documents：稳定文档 ID、逻辑文件名、类型和元数据。
- sections：稳定章节 ID、父节点、顺序、标题、层级及直属正文。
- versions：不可变版本、父版本、操作 ID、内容或删除标记。
- outbox/inbox：待发送操作、已收取待应用操作，支持崩溃后继续处理。
- sync_state/conflicts：拉取游标、已处理操作、冲突分支及解决状态。

章节直属正文与子章节分别存储，避免嵌套内容重复；普通记录可先作为单个内容单元。
标题查询继续支持现有接口；稳定 ID 用于内部同步。章节替换涉及子树时，整个变更集原子提交。
第一版仅自动合并互不重叠的章节编辑；父子重叠编辑、章节结构或整文档重写采用保守冲突检测。
全文更新无法可靠识别章节身份时，不猜测对应关系，走显式结构替换与版本检查。

本地 expectedRevision 继续检查调用方读到的完整文档快照；同步另外使用内容单元的父版本，避免把文件级 revision 当作跨设备合并算法。
INDEX 作为数据库派生视图提供兼容结果，不再维护第二份权威文件。

检索先保持现有大小写不敏感的多词匹配语义；评估 FTS5 trigram 加速，中文短词及不足三个字符的查询保留精确扫描回退，并用测试确认无漏检。

## 2. 同步协议与 Worker

- 每个空间生成独立 spaceId，每台设备独立 deviceId/token；Worker 仅存 token 哈希并检查空间绑定和撤销状态。
- 客户端只持 Worker 访问凭据；D1 databaseId 留在本地部署配置，Cloudflare 管理 token 仅用于部署。
- push 提交操作 ID、实体 ID、父版本和 payload；相同操作重试返回相同结果，相同 ID 配不同内容拒绝。
- Worker 在原子写入中完成去重、版本检查、变更追加和单调序列分配；实施前用 D1 实际能力验证条件竞争行为。
- pull 按服务器游标分页，客户端持久保存收到的页面后才推进接收游标；应用进度单独记录。
- 同一章节的并发分支全部保留并标记冲突，不以客户端时间戳或最后写入者覆盖。
- 删除使用 tombstone；第一版保留历史、不做自动清理，避免离线旧设备复活已删除内容。
- 冲突通过 CLI 查看及显式选择/合并，并生成引用冲突分支的新版本。
- API 限制请求大小、批量数量和分页大小；日志不输出正文、token 或密钥。

## 3. 可选云端加密

空间初始化时固定 plain/encrypted 模式；第一版不提供原地模式切换或复杂密钥轮换。
加密空间使用成熟认证加密实现（候选 Web Crypto AES-256-GCM），随机空间密钥、每次加密独立随机 nonce。
标题、摘要、正文与业务元数据放入加密 payload；协议版本、空间、实体、父版本及操作 ID 绑定为认证附加数据。
服务器仍可观察路由 ID、版本关系、时间与大小；加密不能保证恶意服务器不隐藏历史或拒绝服务。

本地程序与同步容器均视为受信环境，可以直接处理明文。同步程序读写同一空间的本地 SQLite：上传前按空间配置加密，下载后验证解密，并在事务中应用正文、版本和同步状态。
本地写入与待同步操作在同一数据库事务中落地；网络请求在事务外执行，通过稳定操作 ID 和版本检查处理重试及并发修改。
无需独立 transport 数据库、密文搬运层或单独 apply 阶段。加密空间缺少密钥时明确报错，保留游标和待同步状态，不降级为明文上传。
加密密钥与同步 token 分别保存；提供恢复密钥导出和新设备导入，不写入 Git、镜像或日志。
凭据泄漏仍可损害可用性，因此保留本地历史与独立备份；恢复测试属于验收项目。

## 4. 宿主机脚本与配置

拟提供 memory-sync.sh，使用固定镜像引用启动一次性容器：

- sync/status：推拉增量变更、查看待同步及冲突状态。
- 本地管理 CLI 负责 init/import/export/conflicts/backup；Worker 部署单独执行。
- 本地 SQLite 目录读写挂载，同步凭据与可选加密密钥只读挂载；同步容器可以访问明文，日常聊天容器无需云端 token。
- 使用明确 root/space 与 UID/GID，兼容 SQLite 的目录级 WAL/SHM 写入。
- endpoint、spaceId、deviceId、数据库部署 ID 等放在本地忽略配置中，仓库只提交无秘密的示例。
- 同步添加 .gitignore 与 .dockerignore，隔离数据库、凭据、密钥、备份及部署状态。

## 5. 迁移与验收

先使用合成数据跑通两设备原型，再连接现有插件、CLI 与 MCP；真实迁移单独确认。
导入支持 dry-run，保留原始 Markdown/YAML、稳定文档 ID 和备份；导出校验正文、元数据及嵌套章节结构。
切换后旧 Markdown 为只读快照，回退通过导出完成，避免两种后端同时写同一份记忆。

必须通过：

1. 现有接口、权限、短文件直返、分页和 revision 测试；SQLite 运行时与内部旧格式读取器的兼容契约测试。
2. 离线两端编辑不同章节、相同章节、父子章节、删除与旧设备重连。
3. push 响应丢失、重复请求、乱序接收、分页中断、进程崩溃和数据库忙时恢复。
4. 错空间 token、撤销凭据、错误密钥、密文篡改及跨实体重放拒绝。
5. encrypted 模式上传 payload 及云端无明文正文，日志无秘密；本地数据库保持明文，plain 模式同步行为一致。
6. Markdown 往返、中文检索、备份恢复及新设备通过恢复密钥重建。
7. Worker 本地 D1 测试；部署后以合成数据执行真实双端验收，才考虑正式迁移。

## 实施顺序与停靠点

1. 核对官方资料，固定协议与 schema，加入 SQLite 后端和合成数据契约测试。
2. 实现本地双端同步模拟器，验证冲突与幂等，再实现 Worker/D1。
3. 在同步程序中加入可选加密和 Docker 启动脚本，完成集成测试。
4. 提供部署、恢复和迁移说明；由用户确认云资源部署及真实数据迁移。

每步可单独提交和验收。当前已完成本地引擎及普通运行时写入集成：v2 持久化章节身份、操作及分支快照，支持创建文档、保守冲突、tombstone、重试幂等和原子接收游标。日常 update 指定章节且标题结构不变时，按稳定 ID 入队，双端不相交的子树编辑自动合并；updated_at 取较晚值，其余元数据保留。整篇更新、标题结构变化或首次补写旧文档 frontmatter 仍走整篇操作。相同章节结构保持 ID，结构变化建立新身份。无需再次升级 schema；写入或重放带时间戳的新章节操作前，须重新加载所有 v2 写入端。

升级前安装所有写入端的新版本并停止全部写入端（包括已加载的旧插件），运行 `./memory.sh upgrade-sync --root /absolute/database-root --space shared --dry-run`，确认后去掉 `--dry-run`。实际升级在写锁内生成并 fsync 独立 v1 备份，事务升级并返回 backupPath；原有版本和旧 outbox 保留。用 `./memory.sh sync-status --root /absolute/database-root --space shared` 查看本地状态。每次管理一个授权空间，旧运行时代码拒绝 v2。完整回退步骤见同步集成里程碑。

v2 本地 CLI 已支持 `conflicts NAME` 和 `resolve --input FILE|-`：每次操作一个授权空间和一个确切文件名。解决操作同时校验可见 revision 和完整因果状态 token，保留可见元数据、ID、分支历史及独立的可见编辑；复杂分支需手工合并完整 Markdown。重放仅解决该操作因果闭包内的已见冲突对，迟到编辑和并发解决会形成新的冲突。无需再次升级 schema，使用前须更新并重新加载所有 v2 写入端和同步引擎。

tombstone 可检查但不会恢复。恢复、面向操作者的 bootstrap/推拉命令、Worker/D1、可选加密与通用备份恢复 CLI 仍待实现。普通写入遇到冲突或 tombstone 会阻止覆盖。没有云同步、部署或后台网络循环。
